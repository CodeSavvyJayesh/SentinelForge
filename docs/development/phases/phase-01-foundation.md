## 2. Security fix: database password in Git

**Problem.** `backend/alembic.ini` contained
`sqlalchemy.url = postgresql+psycopg://postgres:<password>@localhost:5432/sentinelforge`.
It was committed in `070b081` and pushed to GitHub.

**Fix in code.** The line is now empty with a comment. `alembic/env.py` already injected the URL
from settings, so the hard-coded value was never needed.

**Action required from you (code cannot do this):**

1. **Change the password** — removing it from the file does not remove it from Git history.
   Recommended: create a dedicated `sentinelforge_app` role (SQL in
   [setup.md](../setup.md#1-postgresql-dedicated-application-role-recommended)).
2. Update `backend/.env` with the new credentials.
3. Optional: rewrite history with `git filter-repo`. Once the password is rotated, the leaked
   value is useless, so this is not strictly required.

**Why it matters for this project:** SentinelForge will itself detect hard-coded secrets
(Phase 5). Its own repository must pass that check.

## 3. Backend changes — what and why

### 3.1 Configuration — `app/core/config.py`

| Before | After | Why |
| --- | --- | --- |
| `env_file=".env"` (relative to *current directory*) | Absolute path computed from the file location | Running `alembic`/`pytest`/`uvicorn` from another folder silently lost the config |
| `DEBUG = True` default | `DEBUG = False` | Secure by default; enable explicitly |
| Only `DATABASE_URL` | + `ENVIRONMENT`, pool settings, `LOG_LEVEL`, `LOG_FORMAT`, `CORS_ALLOWED_ORIGINS`, `ENABLE_API_DOCS` | Everything configurable via env (spec rule 6) |
| No validation | Validators: PostgreSQL URL only, no `*` in CORS, log level normalised | Misconfiguration fails at startup, not in production traffic |
| Duplicate import | Removed | — |

`get_settings()` is cached with `lru_cache` so settings are parsed once. `settings` is still exported,
so existing imports (`from app.core.config import settings`) keep working.

### 3.2 Database — `core/database.py`, `core/base.py`, `core/deps.py`

- `pool_pre_ping=True`: a pooled connection is tested before use, so a PostgreSQL restart does not
  cause random errors on the next request.
- `connect_timeout`: health checks fail within seconds instead of hanging.
- Removed `autocommit=False` (legacy SQLAlchemy 1.x argument).
- **Naming convention** on `Base.metadata` (`pk_%(table_name)s`, `ix_…`, `uq_…`, `fk_…`, `ck_…`).
  Without it PostgreSQL invents constraint names, and future migrations that alter/drop
  foreign keys (Phase 3+) become fragile.
- `DbSession = Annotated[Session, Depends(get_db)]` — shorter, typed endpoint signatures.

### 3.3 Timestamps — `models/mixins.py`, `models/user.py`

| Before | After |
| --- | --- |
| `DateTime` (no timezone) | `DateTime(timezone=True)` → PostgreSQL `TIMESTAMPTZ` |
| `default=datetime.utcnow` (Python side, deprecated since 3.12) | `server_default=func.now()` (database side) |
| Repeated in every model | `TimestampMixin` reused by all future models |

Why: naive timestamps are ambiguous (UTC? IST?). Scan history, audit logs and research
metrics (latency, "when was this found") depend on correct time.

Also: removed `index=True` on the primary key (PostgreSQL already indexes it → the extra
`ix_users_id` index only slowed writes), added `server_default=true()` for `is_active`, and a
`__repr__` that never prints `hashed_password`.

### 3.4 Migration `48095f0985ad` — reviewed, not blindly autogenerated

Followed the rule *modify model → autogenerate → review → upgrade → verify*.
Autogenerate produced a correct skeleton, but review found **two real problems**:

1. **Silent data corruption.** Converting `TIMESTAMP → TIMESTAMPTZ` without a `USING` clause makes
   PostgreSQL interpret old values in the *server's* time zone. On a PostgreSQL installed in India
   (`Asia/Kolkata`) every existing timestamp would shift by 5 h 30 min. Fixed with
   `USING created_at AT TIME ZONE 'UTC'` (old values were written by `utcnow()`).
   A test proves it: it inserts a legacy row, sets the database zone to `Asia/Kolkata`, migrates,
   and asserts the instant is unchanged. Removing the `USING` clause makes that test fail
   (checked deliberately).
2. **Different constraint names on old vs fresh databases.** Your existing database has
   `users_pkey`. A fresh database (tests, teammates, CI) gets `pk_users` from the *first*
   migration, because Alembic applies the new naming convention there too. An unconditional
   `RENAME` crashed on fresh databases — the integration tests caught this. The rename is now
   conditional (`DO $$ … IF EXISTS … $$`).

The first migration `453fd78e5b07` was **not edited**: applied migrations are history.

`alembic/env.py` changes: `compare_type` / `compare_server_default` enabled (so autogenerate
detects type/default changes), and `fileConfig(..., disable_existing_loggers=False)` so running
migrations does not silently disable application loggers.
`alembic.ini`: `prepend_sys_path = %(here)s` so Alembic works from any directory.

### 3.5 Structured logging — `app/core/logging.py`

- One JSON object per line (`LOG_FORMAT=json`) or readable text (`LOG_FORMAT=text`).
- Log messages are **event names** (`request_completed`, `database_health_check_failed`) with
  data in fields. This is what the spec's observability section needs later
  (`scan_started`, `llm_request`, …) and what makes latency measurable for the research evaluation.
- Every record carries the current `request_id` automatically (context variable).
- Uvicorn logs go through the same handler; its access log is disabled because our middleware
  logs requests with more context.

Example line:

```json
{"timestamp": "2026-09-17T16:05:52.720658+00:00", "level": "INFO", "logger": "sentinelforge.http",
 "event": "request_completed", "request_id": "394ff2e2…", "method": "GET",
 "path": "/api/v1/health", "status_code": 200, "duration_ms": 34.53}
```

### 3.6 Middleware — `app/core/middleware.py`

- **RequestContextMiddleware**: accepts a client `X-Request-ID` only if it matches
  `^[A-Za-z0-9._-]{1,64}$` (anything else could inject fake log lines), otherwise generates one;
  returns it in the response; logs method, **path without query string** (query strings can
  contain tokens), status and duration.
- **SecurityHeadersMiddleware**: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: no-referrer`.
- Written as raw ASGI middleware instead of `BaseHTTPMiddleware`, which has known problems with
  context variables and streaming responses.
- CORS: explicit origins only, credentials off (auth will use the `Authorization` header).

Order matters: middleware added last runs first. Request context is outermost so even CORS
preflight responses get a request ID.

### 3.7 Error envelope — `app/core/errors.py`, `app/schemas/error.py`

All errors now look like `{"error": {code, message, details, request_id}}`
(details: [API conventions](../../api/conventions.md)).

- `AppError(code, message, status_code, details)` — later phases raise subclasses
  (`ProjectNotFoundError`, …) from services; no HTTP code in business logic.
- 404/405/etc. from FastAPI/Starlette mapped to stable codes.
- Validation errors list field locations but **never echo input values** (a login request
  must not bounce the password back into logs or UIs).
- Unhandled exceptions → generic `INTERNAL_ERROR`; traceback logged with the request ID, never
  sent to the client (spec section 35).

### 3.8 Health — `api/v1/health.py`, `services/health_service.py`, `schemas/health.py`

| Before | After |
| --- | --- |
| DB down → unhandled exception → raw `500` | `503` with a report saying *which* dependency is down |
| Always claimed `"database": "connected"` | Real `up/down` + measured latency |
| SQL in the endpoint | Logic in a service; endpoint only maps status codes |
| — | `GET /health/live`: process liveness without touching the DB (for Docker/CI later) |

Failure text is generic (`Database connection failed`): no host, port or credentials leak.
The design extends naturally to Ollama and the vector DB in Phases 7–8 (`checks.ollama`, …).

### 3.9 Application factory — `app/main.py`, `api/v1/router.py`

`create_app()` builds the app (logging, handlers, middleware, routers). Tests create isolated
app instances; the module-level `app` still exists for `uvicorn app.main:app`.
`api/v1/router.py` is the single place where feature routers get registered (Phase 2 adds
`auth`). Startup/shutdown are logged; the DB pool is disposed on shutdown.

### 3.10 Dependencies and tooling

- `requirements.txt`: direct runtime dependencies pinned to the versions already in your venv.
- `requirements-dev.txt`: pytest, `httpx2` (HTTP client required by Starlette 1.6's TestClient), Ruff.
- `pyproject.toml`: pytest config (`integration` marker) and Ruff rules incl. **`S` (Bandit
  security rules)** — the project's own code is scanned for insecure patterns.
- `scripts/create_test_database.py`: creates `*_test` database safely.

## 5. Frontend changes — what and why

- **JavaScript → TypeScript** (spec requirement). `strict`, `noUncheckedIndexedAccess`,
  `noUnusedLocals`. Vite template files (counter demo, logos, hero image) removed.
- **Layering:** `pages → hooks → services → apiClient`. Components never fetch.
- **`apiClient.ts`:** base URL from `VITE_API_BASE_URL` (no hard-coded URL), 10 s timeout,
  converts the backend envelope into `ApiError {code, message, status, requestId}`,
  distinguishes `NETWORK_ERROR`, `TIMEOUT`, `INVALID_RESPONSE`, `NOT_CONFIGURED`.
- **Runtime validation** of the health response (`isHealthResponse`) — never trust network data.
- **System status page** — the only screen, and it shows *real* backend state:
  loading → healthy / unhealthy (which dependency, latency, request ID) / API unreachable + Retry.
  No placeholder metrics.
- **Design tokens** in `styles/global.css` (dark + light via `prefers-color-scheme`), including the
  severity scale for later phases. Status uses icon + text, not colour alone.
- Accessibility: semantic table with caption, `role="status"` / `role="alert"`, skip link,
  visible focus ring, reduced-motion support.
- ESLint now uses `typescript-eslint`; `vitest` added for unit tests.
